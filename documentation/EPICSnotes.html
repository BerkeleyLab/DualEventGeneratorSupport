Introduction

This support module and soft IOC provide ASYN drivers to control and acquire data from the ALS dual event generator.  The module consists of C source, a database, and engineering screens.  The dual event generator provides timing and RF siganls for each ALS frequency domain.

Database Development

The example application distributed with this support module comes with a database containing all the following records and EDM screens to display them.  All record names begin with the macros $(P)$(R).  Only the portion of the record name following these macros is shown in the following tables

Sequence Waveform Records

These records set the pattern and timing of event codes to be emitted when an event sequence is initiated.  Set FTVL="LONG", NELM="4096", DTYP="asynInt32ArrayOut", INP="@asyn($(PORT) xxx)", where $(PORT) expands to the port name in the eventGeneratorConfigure command and xxx is the numeric value  shown in the following table.

The entries in these records are delay:event pairs.  The first value in each pair is the number of event generator transmitter clocks (~8 ns each) to delay before emitting the event code specified by the second value in the pair.  A delay value of 0 will result in event codes being emitted in adjacent event code slots.

Name
 ASYN
Subaddress
 Description
E1:SEQ0
 0x3000
 Event generator 1, sequence 0.  This is the default injector sequence.
E1:SEQ1 0x3001 Event generator 1 sequence 1.  This is the alternate injector sequence which is automatically disabled after being emitted.
E2:SEQ0 0x3002
 Event generator 2, sequence 0.  This is the sequence used for AR/SR swapout.
E2:SEQ1 0x3003
 Event generator 2, sequence 1.  This sequence is not normally used.

The FPGA internal memory blocks used to hold the sequences are limited to 28 bits of delay value, so delays greater than or equal to 228 cycles (about 2.1 seconds) consume multiple FPGA memory values and thus reduce the number of delay:event pairs that can be stored.

Hardware Triggers

These records set the event code to be emitted when a hardware trigger input is asserted.  Record name "Ee:HW:c" (e=1/2, c=1..4), DTYP=asynInt32 and OUT="@asyn($(PORT) 0x12xy)", where $(PORT) expands to the port name in the eventGeneratorConfigure command and x =1/2, y=0..3.

Software Triggers

Each software trigger is controller by two longout records.  The first, with name "Ee:SW:c" (e=1/2, c=1..4), x =1/2, y=0..3, sets the event code to be emitted.  The second, with name "Ee:SW:c:trig" (e=1/2, c=1..4), DTYP=asynInt32 and OUT="@asyn($(PORT) 0x1100", where $(PORT) expands to the port name in the eventGeneratorConfigure command and x =1/2, y=0..3, causes that event code held in the corresponding "Ee:SW:c:trig" to be emitted when processed.

Sequencer Status Input Record

This mbbiDirector record, "$(P)$(R)SEQ:status", should be configured with SCAN=".1 second", DTYP=asynInt32 and INP="@asyn($(PORT) 0x0010)", where $(PORT) expands to the port name in the eventGeneratorConfigure command.  The scan rate is high since the values present in this record are critical for the timing of injector cycles.  The individual bits in this record are described in the following table.

Bit
 Description
B0 Set when event generator 1, sequence 0 (the default sequence), is enabled.
B1 Set when event generator 1, sequence 1, is enabled.  This sequence is automatically disabled after it has been emitted.
B2
 The currently active, or most recently completed, event generator 1 sequence.
B3
 Set when event generator 1 is emitting a sequence.
B4
 Set when event generator 2, sequence 0, is enabled.
B5
 Set when event generator 2, sequence 1, is enabled.  This sequence is automatically disabled after it has been emitted.  This sequence is not used during normal operation.
B6
 The currently active, or most recently completed, event generator 2 sequence.  Never set during normal operation since only sequence 0 is used.
B7
 Set when event generator 2 is emitting a sequence.

FPGA update on reconnect

The IOC attempts to automatically restore FPGA settings following an FPGA restart.  This is achieved through a calcout record ($(P)$(R)reconnChk_) that monitors the STAT field of a periodically-scanned readback record ($(P)$(R)sysmonTrig_) and causes a number of event and fanout records to process when that status returns to 0 or when the FPGA 'power up' condition is detected.  The fanout records in turn cause the various input and output records to process and read from or send their values to the FPGA.

IOC Startup Script

Communication with a dual event generator IOC is configured at IOC startup with theT eventGeneratorConfigure command.  Arguments must appear in the order shown below.
  1. The ASYN port name.  The value is arbitrary, but the dbLoadRecords command which loads the database described above must specify the same value.
  2. The IPv4 address of the dual event generator FPGA.
  3. The priority at which the port threads will run.  A value of 0 results in the default medium priority.
